# Contract Parser v2 — Контекст проекта

## Репозиторий
https://github.com/llCoolGamell/contract-parser
Ветка: **v2**
Последний тег: **v2.1.0**

## Структура файлов
- `main.py` — GUI (PyQt5): список файлов, drag-and-drop, кнопки, обработка
- `parser_engine.py` — парсинг HTML/PDF контрактов с zakupki.gov.ru
- `excel_handler.py` — запись данных в Excel (.xlsx)
- `.github/workflows/build.yml` — CI: сборка .exe при пуше тега `v*`
- `requirements.txt` — зависимости Python

## Что реализовано

### GUI (main.py):
1. **Список файлов** с drag-and-drop поддержкой (HTML/PDF)
2. **❌ кнопка** справа от каждого файла — клик удаляет файл из списка
3. **Проверка дублей** — при добавлении файла, который уже есть, показывается ошибка «Такой документ уже добавлен»
4. **❌ → ✅** после успешной выгрузки, файлы с ✅ НЕ выгружаются повторно в текущей сессии
5. **Кнопка «📂 Открыть Excel»** (оранжевая, справа внизу) — открывает текущий Excel файл
6. **ProcessThread** — обработка файлов в отдельном потоке, поддерживает несколько ContractData на файл (multi-row)

### Парсер (parser_engine.py):

#### Основной режим: Multi-row (v2.1.0+)
Один HTML файл может содержать **несколько позиций** лекарственных препаратов. Каждая позиция из раздела «Дополнительная информация о лекарственном препарате» выводится **отдельной строкой** в Excel.

- `parse_file()` возвращает `list[ContractData]` (не одиночный объект)
- `_parse_object_table()` — парсит таблицу объектов закупки (п. 3.1) в `{row_num: {name, qty, unit_price, sum}}`
- `_parse_drug_entries()` — парсит все записи из «Дополнительная информация о лекарственном препарате»
- `_build_contracts()` — собирает `ContractData` для каждой позиции, сопоставляя с таблицей объектов по `obj_num`

#### Извлекаемые поля:
| Столбец Excel | Источник |
|---|---|
| Собственник товара | Сокращённое наименование заказчика → аббревиатура (МЗ и т.д.) |
| тип | Всегда «Основная заявка» |
| № договора | Номер контракта + дата |
| № аукциона | Номер извещения |
| МНН | Из ГРЛС (часть до двоеточия). При различии с объектом закупки — оба через запятую |
| Торговое наименование | Из «Торговое наименование, номер РУ» (часть до «,ЛП») |
| Лек. Форма | Из ГРЛС (часть ПОСЛЕ двоеточия, без МНН) + «№X» (X = кол-во потреб. единиц в упаковке). Если форма содержит «мл» — формат `{qty} мл №1` |
| Ед. изм. | Всегда «упак.» |
| Общее кол-во | `total_qty / qty_per_consumer` = количество упаковок |
| Производитель | Держатель РУ / Производитель (без кода страны) |
| Цена ед. продукции | `total_price / quantity_packages` |
| Общая цена | Сумма из таблицы объекта закупки (per-row) |
| поставщик | Сокращённое наименование поставщика |
| способ размещения | Способ определения поставщика |
| Сумма | = Общая цена |

#### Fallback: Single-row
Если парсер не находит multi-row структуру, используется старый режим (одна строка на файл).

### Excel (excel_handler.py):
1. **Дубли строк** — определяются и подсвечиваются **СИНИМ** + сообщение «При выгрузке обнаружены дубли»
2. **Жёлтый цвет** для «Лек. Форма» когда содержит только МНН (нет формы выпуска)
3. **Красный цвет** для несовпадений количества из 3 источников (Объём закупки, Потреб. ед., Общее кол-во)

## Зависимости (requirements.txt)
- PyQt5 — GUI
- beautifulsoup4 + lxml — HTML парсинг
- openpyxl — Excel запись
- pyinstaller — сборка .exe (CI)

## Важно
- Ветки `init` и `main` — бэкап v1, **НЕ трогать**
- Работа ведётся в ветке `v2`
- Python 3.10+
- `parse_file()` возвращает `list[ContractData]` — всегда список, даже для одного результата
